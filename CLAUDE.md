## What it is
A single-page site (also installable as a PWA) that shows WoW Forever streamers' characters as trading cards. The front of a card has the character render, level, guild, live Twitch status and a Stats/Profs panel. Tap it to flip to the equipped gear in a character-sheet layout, with tooltips comparing Forever and Classic. Each card also has Talents and Twitch panels, and a news ticker runs along the top of the page.

- Live: https://blaqkfyre.github.io/wow-forever-tracker/ (GitHub Pages from `main`, repo `BlaqkFyre/wow-forever-tracker`)
- Local copy: `C:\Users\Ruth\Documents\GitHub\wow-forever-tracker` (Luke uses GitHub Desktop)
- Plain HTML, CSS and JS with no build step. Data is generated by Python in GitHub Actions.

## Files
| File | Role |
|---|---|
| `index.html` | The whole front end: CSS, the `ROSTER` block, cards, gear tooltips, talents popup, ticker, and Add/Remove. About 1,550 lines. |
| `roster.json` | **The source of truth for streamers and characters.** `refresh.py` copies it into the `const ROSTER = [...]` block in index.html. |
| `gear-data.js` | Generated `window.GEAR`: items `I` (name, quality, ilvl, icon, new/changed/same, Forever and Classic lines, source) and gear per character slug `C`. |
| `chars.js` | Generated `window.CHARS`: stats `s` and talents `t` per character slug |
| `events.js` | Generated `window.EVENTS`: ticker events (level ups, hitting 60, loot, professions, guild, rep, cards added or removed) |
| `history.json` | Generated daily `[level, ilvl]` for each character slug |
| `talent-trees.js` | `window.TREES`: talent tree layouts for each class |
| `sprite.webp`, `showcase.webp`, `talents.webp`, `talent-icons.webp` | Generated icon sprite sheets |
| `renders/<slug>.webp` | Character renders. EU characters are under `renders/eu/`. |
| `tools/refresh.py` | Pulls every character from the official WoW Forever Armory, rebuilds all the generated files, handles Add/Remove requests, and writes the commit message |
| `tools/vodname.py` | When an Add request has no character name, it finds the character by OCR-ing the streamer's recent Twitch VODs (ffmpeg + tesseract) |
| `.github/workflows/refresh.yml` | Runs `refresh.py` every 3 hours, on manual run, on pushes to roster.json or the tools, and on Add/Remove issues. Commits as github-actions[bot]. When a run fails it writes `.github/last-error.log`. |
| `.github/ISSUE_TEMPLATE/` | Forms for Add a streamer (channel, character optional, realm, display name) and Remove a streamer |
| `manifest.webmanifest`, `icon-*.png` | PWA install |
| `c/*.html`, `share-links.md` | Generated solo card share pages, and the list of their links |
| `previews/gear-style-previews.html` | Old mockups of the gear styles. The live page doesn't use it. |

The Armory sometimes returns a character without stats or item levels. `refresh.py` then keeps that character's last known stats (from `chars.js`), ilvl (from `roster.json`) and per-item levels (from `gear-data.js`), and says so in the workflow log.

The Armory can also lag behind the game on level. Add `"level_seen": N` to a character in `roster.json` and the refresh shows that level until the Armory reaches it, then removes the field.

Don't hand-edit the generated files. Change `refresh.py` or `roster.json` and let the workflow rebuild them. Scripts load with `?v=<hash>` version strings, and `refresh.py` updates those.

## How Add / Remove work
- The page's Add button and the 🗑 button on a card open a pre-filled GitHub issue form. The labels `add-streamer` and `remove-streamer` trigger the workflow, which edits `roster.json`, rebuilds, comments on the issue and closes it.
- If someone other than Luke asks to remove a card, it waits until Luke adds the `approved` label.
- Live Twitch status comes from DecAPI and is checked every 15 minutes in the browser.

- **Solo share pages for every card:** `c/<character>-<code>.html`, made by `share_pages()` in refresh.py on every run. The code is stored once per character as `"share"` in roster.json (kept out of index.html's ROSTER block), so links never change; pages for removed characters are deleted. `share-links.md` lists every link. Each page fetches index.html and sets `window.SOLO_FORCE`, so only that card shows (no page controls, no links back, noindex, no PWA install). On PC the card is half the fill-the-window size; on phones it's the same size as on the tracker. There is deliberately no `?solo=` URL option. Abg Slayer keeps `c/abg-slayer-gtCETHRJ.html`.
